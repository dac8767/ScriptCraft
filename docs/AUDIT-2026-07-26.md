# ScriptCraft — speed / efficiency / security / stability audit — 2026-07-26 (v4.62)

Delta audit on top of `AUDIT-2026-07-10.md` (security, v0.54) and
`EFFICIENCY-AUDIT.md` (cleanup backlog, landed as T1–T7): re-verified the old
findings, swept everything shipped since (~100 versions: window chrome, the
suggestion system, decorations, rules editor), and checked stability angles the
earlier passes didn't cover. Safe fixes were applied and shipped with this
audit; substantial changes are listed for Derek's approval at the bottom.

## Applied in v4.62 (safe — gates + live smoke green)

1. **Dependency security fixes** — `npm audit fix` (semver-compatible only):
   `ws` (high ×2: memory disclosure + DoS), `linkify-it` (high),
   `markdown-it` (moderate ReDoS), `dompurify` (moderate) all patched via
   lockfile. Production vulnerabilities: 6 → 2 (the remaining pair is the
   react-router item below). Full suite (651) + build + live editor smoke
   passed on the updated tree.
2. **Root error boundary** (`AppErrorBoundary.tsx`, wired in `main.tsx`) —
   a throw during any component render used to unmount the whole tree: white
   screen, no message, no way back. Now: readable crash panel, the stack, a
   Reload button, and the reassurance that autosave (2s debounce) has the
   script. Init-time failures were already handled; render-time ones were not.
3. **Build warning removed** — `saveLocations.ts` dynamically imported
   `odraftFormat` which is statically imported elsewhere, so the chunk could
   never split; every build printed `INEFFECTIVE_DYNAMIC_IMPORT`. Now static.

## Verified healthy (no action needed)

- **S1 path traversal — FIXED** since the last audit: `security.py`
  (`validate_path_params` router dependency + `assert_safe_resource_id`)
  rejects traversal primitives before any path join.
- **S2 asset upload — FIXED**: `ALLOWED_ASSET_EXTENSIONS` whitelist enforced
  at save time.
- **localStorage robustness**: every `JSON.parse` of stored state
  (viewState, bookmarks, element/transition overrides, notebook, outline
  presets, project cloud keys) is try/catch-guarded with shape validation —
  corrupted storage cannot white-screen the boot.
- **Listener hygiene**: zero add/remove imbalances for document/window
  listeners across `components/` and `editor/` (scripted sweep).
- **No `eval`/`new Function`.** The three `innerHTML` sites are: DOMPurify-
  sanitized (`MiniRichText`), app-generated markup (`screenshot.ts` menu),
  and the Index Cards drag ghost (S6 — low, content was React-escaped at
  first render).
- **Save pipeline**: 2s debounced autosave with a real error surface
  (`reportSaveError`); CONT'D re-stamping debounced at 800ms.
- **CORS** stays localhost/LAN-scoped with credentials — fine for the
  local-first topology; the S4 note (hosted deployments must pin
  `CORS_ORIGINS`) still stands.

## Substantial changes — NEED APPROVAL

1. **react-router major upgrade** — the 2 remaining high advisories cover
   `react-router` 7.12.0–8.2.0; the fix is a breaking-range bump
   (`npm audit fix --force`). Routing here is shallow (BrowserRouter +
   a few routes), so the upgrade is likely an hour including a nav retest —
   but it is not lockfile-only.
2. **Debounce the per-keystroke rescans** — `updateScenes` and
   `updateCharacters` each walk the ENTIRE document on every editor update
   (on top of pagination + decorations). This is the largest avoidable
   per-keystroke cost on a feature-length script. A ~300ms trailing debounce
   would cut it; the visible change is the Scenes panel / character list
   updating a beat after typing pauses rather than mid-keystroke.
3. **Tauri fs scope** — the capability file allows `$HOME/*` and `$HOME/**`,
   so the renderer process can touch anything under the home directory. The
   hardening is scoping to `$APPDATA` + dialog-granted paths, but Save As /
   local-folder autosave flows depend on the current breadth — needs a
   desktop retest to change.
4. **Tauri CSP tightening** — `connect-src` allows all `https:`/`wss:` and
   styles allow `unsafe-inline`. Pinning the exact hosts (Google fonts/auth,
   the dictionary CDN until it's rehosted, the collab server) would contain
   exfiltration in any future XSS, at the cost of breaking silently if a
   legitimate endpoint is missed. Do after the CDN rehost decision.
5. **Backend Python deps** — not scannable from this sandbox; one command on
   the Mac: `pipx run pip-audit -r backend/requirements.txt`.

Standing items already on the books (CLAUDE.md §6): rotate the GitHub PAT,
rehost dictionaries off Proteus's CDN, brand art + licenses.

# Follow-up — v4.82 (2026-07-26, Derek approved "continue with these")

## 1. Rescans gated on tool-open — DONE (v4.82)
Derek's refinement: "the lists should only continually refresh if the tool in
question is open. it also should refresh when opened initially. it does not
need to constantly refresh if the tool is closed."

Implemented in `ScreenplayEditor` rather than as the proposed debounce, so
there is no visible lag when a list IS open:

* `openToolKey` (activeTool | activeToolRight | tempTool | fullscreenTool)
  answers "is tool X open anywhere", including the fullscreen takeover.
* Consumers, verified by grep — these are the ONLY readers of
  `store.scenes` / `store.characters`: Scenes, Navigator, Characters
  (its Relationships view reads characters).
* Doc changes set a dirty flag; the scan runs immediately when a consumer is
  open, and catches up the moment one opens.
* **The scene scan is not purely a list feeder** — it stamps scene numbers
  INTO the document, and those print. So `sceneNumbersVisible` keeps it live
  no matter which tools are open. Missing this would have silently dropped
  scene numbers from printed pages.
* **The character scan also feeds autocomplete** — so entering a character
  node refreshes if dirty, even with every tool closed. Driver-verified: type
  SARAH with all tools closed, start a second character line, "SA" still
  offers SARAH.

## 2. react-router advisories — DONE (v4.82), and npm's advice was wrong
`npm audit fix --force` proposed a **downgrade** to react-router-dom 7.11.0.
The advisory range is 7.12.0–8.2.0, and `react-router-dom` itself stops at
7.18.1 — v8 ships as the merged `react-router` package. So the fix that moves
FORWARD is: `react-router@8.3.0`, imports rewritten from `react-router-dom` to
`react-router` (9 files, mechanical — the app only uses BrowserRouter, Routes,
Route, useNavigate, useParams, useSearchParams), and `react-router-dom`
uninstalled.

`npm audit --omit=dev` now reports **0 vulnerabilities** (was 2 high).
Driver-verified on v8: `/` → editor, `/settings`, `/reset-password`,
`/verify?email&code` (search params read correctly), and the params route
`/project/:projectId/edit/:scriptId`. No console errors.

## 3. Tauri fs scope — NOT SHIPPED, deliberately. Plan + test list below.
The capability grants `$HOME/*` + `$HOME/**` to mkdir / write-file /
write-text-file / read-file / read-text-file / remove / exists / fs:scope.

What the breadth is actually for (grep of `@tauri-apps/plugin-fs` users):

| Site | Path source |
|---|---|
| `services/local-storage.ts` (the real script store) | `BaseDirectory.AppData` — **does not need $HOME** |
| `services/file-fallback-*.ts` | AppData |
| `SaveAsDialog` (writeTextFile, remove) | a path the user picked in the native dialog |
| `services/saveLocations.ts` (mirror copies) | a user-chosen folder |
| `utils/screenshot.ts` | the user-chosen screenshot folder |
| `AssetManager` (readFile) | a user-picked file |

So the core store would be happy with `$APPDATA` alone; the breadth exists
only for paths the user explicitly chose. Tauri v2's dialog plugin does not
extend the fs scope for picked paths, which is why `$HOME/**` was used.

**The fix, when it's done:** route the user-chosen-path writes through the
existing Rust command (`save_text_to_path` in `src-tauri/src/lib.rs`), which
bypasses the plugin scope entirely, then narrow the fs capability to
`$APPDATA/**`.

**Why it isn't in this release:** it rewrites the save path — the one piece of
this app whose failure loses a writer's work — and it cannot be exercised in
this sandbox at all (no Tauri runtime; the driver is a browser). Shipping an
untested change there would be exactly the "silent no-op" this project treats
as the cardinal sin, with the worst possible blast radius. It wants a session
of its own, with Derek at the Mac running:

1. Save As → a folder outside AppData, then reopen the file.
2. Settings ▸ Save Options → local folder mirror on; edit; confirm the copy.
3. Auto-save snapshots to a local folder.
4. Screenshot with a screenshot folder set.
5. Insert an image from disk; Asset Manager import.
6. A fresh profile (no AppData yet) → first save must still create the store.

## 4. CSP — DOCUMENTED DECISION (no change)
`connect-src` stays broad and `style-src` keeps `unsafe-inline`. Reasons, so
this doesn't get "fixed" by a future pass and break the app:

* **connect-src must stay open-ended** while the cloud API base is a
  user-editable setting (Settings ▸ System ▸ Collaboration Server) — pinning
  hosts would break every self-hosted server, silently, at runtime.
* **style-src 'unsafe-inline'** is required by React inline styles, which this
  UI uses throughout (every measured tool window, the to-scale title page, the
  ruler overlays).
* The genuinely useful tightening is `script-src` (already effectively
  self-only) and removing the dictionary CDN dependency — tracked as the
  rehost item in CLAUDE.md §6. Revisit CSP right after that rehost, when the
  external host list finally stops moving.
